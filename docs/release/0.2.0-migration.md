# Migrating to MarkdownKit 0.2.0

0.2.0 is a breaking release. The rendering pipeline became immutable and
session-owned, remote image loading and link activation became opt-in, and the
platform floor moved. This guide covers every removal and every changed default.

If you only ever wrote `MarkdownText("…")` and `MarkdownEditor(text:)`, the two
things that can change under you are the **platform floor** and **Dynamic Type**;
skip to those sections.

---

## Platform floor

| | 0.1.x | 0.2.0 |
|---|---|---|
| iOS | 26.0 | **18.0** |
| macOS | 26.0 | **15.0** |

The floor moved *down*. Nothing that built against 0.1.x stops building for this
reason. `Scripts/check-platform-floors.sh` is the gate that keeps the sources and
`Package.swift` agreeing.

---

## Remote images are off until you opt in

0.1.x fetched any `![alt](https://…)` it found. 0.2.0 renders a placeholder
instead, and nothing leaves the process, until the host says otherwise:

```swift
MarkdownText(markdown)
    .markdownRemoteImages(.defaultHTTPS)
```

`.defaultHTTPS` is `.https(requestTimeout: .seconds(15), resourceTimeout: .seconds(30))`:
HTTPS only, an isolated `URLSession` with no shared cookies or credentials,
PNG/JPEG/GIF/WebP/HEIC/HEIF only, a 20 MiB encoded body cap, 8192 pixels per
dimension, 32 animation frames and 40 million cumulative pixels. Timeouts are
clamped to 1…120 seconds. A host that needs different limits supplies its own
loader — the caps above that are decode-side still apply, because every image
this library materializes goes through the same validated construction:

```swift
MarkdownText(markdown)
    .markdownRemoteImages(MarkdownRemoteImageConfiguration(loader: MyLoader()))
```

**Cache namespace.** A configuration's `configurationID` is what decides whether
two views may share a resolved image. `MarkdownRemoteImageConfiguration(loader:)`
mints a fresh `.uniqueInstance()` id each time, so two configurations wrapping the
same loader do *not* share — which is the safe default, because two hosts can wrap
one loader and mean different things by it. Pass an explicit
`.semantic(namespace:version:)` id when the outputs really are interchangeable, and
bump the version when they stop being:

```swift
MarkdownRemoteImageConfiguration(
    loader: MyLoader(),
    configurationID: .semantic(namespace: "my-app-images", version: 1)
)
```

**Failures never carry a URL.** `onMarkdownResourceError` receives a
`MarkdownResourceFailure` whose `origin` is a `SanitizedMarkdownOrigin` — scheme,
host and port, never the path or query — and a `category` rather than an
`NSError`. Demo and log surfaces can print it directly.

```swift
MarkdownText(markdown)
    .markdownRemoteImages(.defaultHTTPS)
    .onMarkdownResourceError { failure in
        // `origin` is optional: a failure with no usable URL carries none.
        logger.warning("\(failure.category) from \(failure.origin?.description ?? "unknown")")
    }
```

## Links are decided by a policy and opened by a handler

0.1.x handed every link to the system opener. 0.2.0 splits the decision from the
activation:

```swift
MarkdownText(markdown)
    .markdownLinkPolicy(.webOnly, handler: PlatformMarkdownLinkHandler.shared)
```

That is also the default, so a host that wants HTTP/HTTPS through the platform
opener needs no code. Anything else needs **both** halves:

```swift
struct MyAppScheme: MarkdownLinkPolicy {
    func disposition(for request: MarkdownLinkRequest) -> MarkdownLinkDisposition {
        request.url.scheme == "myapp" ? .allow(request.url) : .reject
    }
}

MarkdownText(markdown)
    .markdownLinkPolicy(MyAppScheme(), handler: PlatformMarkdownLinkHandler(allowedSchemes: ["myapp"]))
```

A policy that permits a scheme the handler does not open is a programming error,
and `PlatformMarkdownLinkHandler` traps on it in debug rather than opening it.

`MarkdownLinkPolicy` is `Sendable` and pure: it decides, it never opens anything
and never touches platform state, and its decision runs on the cooperative pool.
Do not block or perform I/O in it — a policy that waits on a lock, a file or the
network holds a pool thread for that whole time. `MarkdownLinkHandler` is
`@MainActor` and is the only place the library calls a platform opener.

**Replacement semantics.** `markdownLinkPolicy(_:handler:)` derives identities
from the policy's *type* and the handler's *object identity*, so re-evaluating a
SwiftUI body does not read as a replacement. The live policy value is forwarded on
every update regardless, so a stateful policy takes effect as soon as the body
carrying the new value is evaluated. A host that needs to control the identities
itself uses `markdownLinkConfiguration(_:)`.

## Copy is exact, and source copy is a separate command

0.1.x had one Copy, and it returned **Markdown source** — selecting rendered text
and pressing ⌘C pasted `**bold**`, not `bold`. That is the wrong default for a
read-only rendered view, and it could hand over more source than the selection
covered. 0.2.0 splits it in two:

- **Copy** (⌘C, unchanged shortcut, **changed result**) — exactly what is on
  screen, with attachments and the overflow table's placeholder substituted whole.
- **Copy Markdown Source** — the source region the selection covers, which is what
  ⌘C used to give.

A host that wants the 0.1.x behaviour on ⌘C calls `markdownSourceSelectionResult()`
from its own command.

Both are reachable programmatically:

```swift
let rendered = label.renderedSelectionResult()          // always .exact
let source = label.markdownSourceSelectionResult()      // check .granularity
```

`MarkdownCopyResult.granularity` says how faithful the source copy is:

| Granularity | Meaning |
|---|---|
| `.exact` | The contiguous source region between the selection's endpoints. It can include source belonging to no block — a link reference definition between two selected paragraphs — because dropping it would leave `[text][ref]` unresolvable. |
| `.blockExpanded` | The selection cut into a block and the whole block's source was returned; inline source offsets do not exist. Check for this if you must not paste more than was selected. |
| `.renderedFallback` | No source mapping was available. Approximate syntax, clamped to the selection, not guaranteed to reparse as the same document. |

Menu titles are overridable process-wide through `MarkdownCopyCommandTitle.copy`
and `.markdownSource`; the defaults are localized by the package.

## Default fonts follow Dynamic Type

`RenderStyle.default` now registers every default font as scalable, so a document
follows the reader's text size. This is a behaviour change for a host that shipped
a fixed-size document with the default style.

Two ways to keep the old behaviour:

```swift
// Every role pinned:
MarkdownText(markdown).markdownStyle(.fixedDefault)

// One role pinned:
var style = RenderStyle.default
style.pinFont(for: .body)
```

A role stops following the reader as soon as its stored font differs in size from
the size it was registered at, so assigning `.systemFont(ofSize: 22)` is already an
opt-out. Assigning a font at *exactly* the registered size is indistinguishable
from the registered one, which is what `pinFont(for:)` is for.

The inverse — a custom face that scales — is `MarkdownScaledFont`:

```swift
var style = RenderStyle.fixedDefault
style.setFont(MarkdownScaledFont(base: myFace, relativeTo: .body), for: .body)
```

Headings keep at least the square root of the ratio they were declared at, so the
hierarchy survives the accessibility categories rather than compressing into the
body size the way the platform's own text styles do.

On iOS the view mirrors the system trait automatically. On macOS, which has no
system-wide text-size setting, assign `MarkdownLabelView.contentSizeCategory`
yourself.

## The compatibility renderer is gone

`AttributedStringRenderer` and its mutable caches were the 0.1.x rendering entry
point. They are removed, along with:

There is deliberately **no public replacement that hands a host an
`NSAttributedString`**. Producing one requires the main actor, a resolved
resource set and a lease over it, and the previous API let a host hold the string
after the resources under it were released. Use `MarkdownText`,
`MarkdownStreamingText` or `MarkdownLabelView`, which own a render session that
does the whole sequence and keeps the resources alive exactly as long as the
snapshot that references them.

`RenderPreparer` remains public for the off-main-actor half — parsing and
document preparation, which produces a `Sendable` `RenderDisplayModel` and no
platform objects. Materialization is `package`.

| Removed | Replacement |
|---|---|
| `AttributedStringRenderer` | A view that owns a render session, per above. |
| `AttributedStringRenderer.render(_:)`, `.renderBlock(_:)`, `.blockSeparator()` | `MarkdownLabelView.setMarkdown(_:)` / `appendMarkdown(_:)`, or `MarkdownText(_:)`. For the display model alone, `RenderPreparer(configuration:).prepare(_:)`. |
| `.imageCache`, `.mathCache`, `.svgBlockCache` | Resources are owned by the session and leased for the lifetime of the snapshot that uses them. There is no host-writable cache. |
| `.mathRasterScale`, `.svgRasterScale` | Taken from the view's display scale. |
| `.mathRendererGeneration`, `.svgRendererGeneration` | `MarkdownConfigurationID` on the renderer configuration. |
| `.style` | `RenderConfigurationSnapshot`, produced by `RenderStyle.snapshot(generation:)`. |
| `MarkdownSourceHighlighter` | Internal to the editor. |
| `SyntaxHighlighter.highlight(…)` | Internal. |
| `DocumentParser.parsedBlocks` | `MarkdownDocument(parsing:).blocks` |

`RenderStyle` is no longer `@unchecked Sendable`. It holds platform fonts and
colors, which are not `Sendable`, and the compiler now says so; cross-actor work
uses `RenderConfigurationSnapshot`, which is a value and carries font descriptors
as archived bytes rather than platform objects. A host that stored a `RenderStyle`
in a `Sendable` type has to move it to the main actor or store the snapshot.

## The math and SVG load coordinators are no longer public

`MathLoadCoordinator.shared` and `SVGBlockLoadCoordinator.shared`, with
`glyph(for:)`, `awaitGlyph(for:)`, `loadIfNeeded(…)`, `drain()`, `setRenderer(_:)`,
`invalidateForScaleChange()`, `isNegativeCached(_:)` and `generation`, were a
process-global mutable cache reachable by any host. They are internal now, and a
renderer is installed through a typed configuration instead:

```swift
// 0.1.x
MarkdownText(markdown)
    .mathRenderer(MathJaxRenderer())
    .svgRenderer(SwiftDrawSVGBlockRenderer())

// 0.2.0
MarkdownText(markdown)
    .mathRenderer(MathRendererConfiguration(renderer: MathJaxRenderer()))
    .svgRenderer(SVGRendererConfiguration(renderer: SwiftDrawSVGBlockRenderer()))
```

Hold the configuration in `@State` rather than constructing it inside `body`: a
new instance on every body evaluation is a new identity, which invalidates the
view's resolved resources and re-rasterizes everything.

`MathJaxRenderer` and `SwiftDrawSVGBlockRenderer` are now actors rather than
`@unchecked Sendable` classes; `MathRenderedGlyph` and `SVGBlockGlyph`, which
carried a bare `PlatformImage`, are replaced by leased resources the session owns.

## Configuration identity, in one place

`MarkdownConfigurationID` decides what may be shared and what counts as a
replacement.

- `.uniqueInstance()` — never shares. The default wherever a host supplies its own
  object, because two hosts can mean different things by the same object.
- `.semantic(namespace:version:)` — shares with any other configuration carrying
  the same id. Use it only when the outputs are genuinely interchangeable, and bump
  `version` when they stop being.

The built-in default style's id is derived from its resolved tokens, and the
reader's text-size category is one of them: a size change is therefore a different
configuration rather than a cache hit at the wrong size. **This id string changed
in 0.2.0** — anything a host persisted keyed on
`MarkdownRenderConfiguration.default`'s id is invalidated by the upgrade.

## Known gaps in 0.2.0

- A resolved SVG code block does not scale with the reader's text size, while math
  does. The rasterizer's contract is fit-width and no-upscale, and changing it is a
  change to the public `SVGBlockRendering` protocol.
- Table cell padding and hairline rules (the heading rule, the quote bar) do not
  scale with the text size. Deliberate: scaling cell padding widens an overflow
  overlay that is already the reader's escape hatch.
- `MarkdownLinkRequest.sourceRange` is always `nil`. The field is part of the
  public decision contract and is kept for a policy that discriminates by position.
