# 文本选择与引用命中修复

## 根因与处理

- UITextInput 的首行矩形错误地转换成窗口坐标，选区矩形未标记起止端点，受限定位忽略传入范围。现统一视图坐标并补齐端点和范围约束。
- App 实际长按日志确认：同一触点 `(22, 70.33)` 首次返回文档末尾 87，随后返回正确位置 35，系统将两者连成选区。改为按渲染行及字符映射定位，不再依赖该插入点导航路径。
- 自定义点击手势清空系统刚建立的选区。移除这段重复控制，由 UITextInteraction 管理选择与收起。
- 引用保持小字形，周围空白点击区扩展至最多补足 44pt；精确普通文字命中优先保护，相邻链接选最近字形。链接使用 highlight 几何，与选区 selection 几何分开。

## 评审与验证

- Claude Code 两轮定向评审，实际模型均为 claude-opus-5-5，Fast 关闭。报告归档 `.artifacts/text-selection/`。
- 首轮指出扩大命中区域可能抢普通文字：新增回归先红后绿。第二轮指出普通文字保护仍依赖不稳定的 closestPosition：最终按渲染行实现，同时修正失效注释。最终行定位改动以测试和 App 复现验证，未冒称已获第三轮 Claude PASS。
- iOS 26.4 模拟器：MarkdownTextSelectionTests + MarkdownLinkPolicyTests，22 项通过，覆盖窗口坐标、选区端点、约束范围、中文换行、emoji、原生选词、引用近点及普通文字保护。
- App UI：长按第二段 Apple → 系统拷贝 → 输入框粘贴 → 精确断言 Apple；引用数字下方 5pt 点击打开对应来源。1 条 UI 测试通过，并人工核对选区截图。
- 链接隔离脚本、变更文件格式与 diff 检查通过。未跑 iOS18/macOS15 发布矩阵；未宣称完成所有系统版本、横屏或超长文档性能验收。
- 临时诊断日志已从源码删除。截图和完整测试日志由 App 的 `.build/evidence/text-selection/` 保存。
